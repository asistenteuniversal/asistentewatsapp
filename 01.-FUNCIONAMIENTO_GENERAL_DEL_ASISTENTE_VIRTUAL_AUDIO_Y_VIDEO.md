## INTRODUCCIÓN Y VISIÓN GENERAL DEL PROYECTO

**Neon Avantar** es un asistente virtual inteligente premium diseñado con un enfoque híbrido. Combina la potencia y fluidez de una interfaz web reactiva de alta estética con la infraestructura nativa de Android, logrando ejecutar la API en tiempo real más avanzada de Google: **Gemini Live Preview (WebRTC)**.

El objetivo central del proyecto es proporcionar una experiencia de usuario "stealth" (oculta y elegante). Mientras el usuario interactúa con una carátula minimalista con acabados negros y dorados metálicos en el frente de su pantalla, en el fondo del procesador se ejecuta una instancia completa del entorno de desarrollo de inteligencia artificial de Google (**Google AI Studio**), procesando voz, video e instrucciones de manera bidireccional y sin latencia.

Este documento detalla cada aspecto del funcionamiento del sistema, sirviendo como guía maestra para futuros desarrolladores o actualizaciones del proyecto.

## 1. ARQUITECTURA DE SOFTWARE E INTEGRACIÓN HÍBRIDA

El proyecto no es una aplicación nativa tradicional ni una página web simple, sino una **arquitectura híbrida superpuesta**. Consta de un chasis nativo desarrollado en Java (`MainActivity.java`) que controla y aloja dos navegadores internos (`WebView`) independientes y concurrentes.

```
┌────────────────────────────────────────────────────────┐
│ CAPA 2 (Frente): webViewNeon (Página 1)                │
│ - Renderiza NeonCoverLayer.tsx (React/TypeScript)      │
│ - Aloja los botones, animaciones de pulso y cronómetro │
│ - URL: https://neon-studio.onrender.com                │
├────────────────────────────────────────────────────────┤
│ CAPA 1 (Fondo): webViewStudio (Página 2)               │
│ - Carga la consola interactiva de Google AI Studio     │
│ - Inicia la transmisión de video WebRTC en vivo        │
│ - URL: https://aistudio.google.com/live?...            │
└────────────────────────────────────────────────────────┘
```

### A. El Contenedor Nativo Android (`MainActivity.java`)
Es el motor que levanta el entorno de ejecución en el dispositivo físico. Sus responsabilidades críticas son:
1. **Configuración de Permisos en Caliente:** Solicita y valida los permisos a nivel de sistema operativo para `RECORD_AUDIO`, `MODIFY_AUDIO_SETTINGS` y `CAMERA`, indispensables para que el navegador de Google pueda utilizar el hardware del celular.
2. **Habilitación de Recursos del Navegador:** Configura las políticas de almacenamiento `DomStorageEnabled`, bases de datos locales `DatabaseEnabled`, ejecución de JavaScript, y cookies de terceros (requeridas para el inicio de sesión de cuentas de Google).
3. **Reproducción Automática:** Desactiva la restricción de interacción física para reproducción de audio (`MediaPlaybackRequiresUserGesture = false`), permitiendo que la voz de la IA se escuche de inmediato en cuanto se conecte la llamada.

### B. El Layout y Ordenamiento Z-Index (`activity_main.xml`)
Utiliza un contenedor de tipo `ConstraintLayout` para superponer ambos WebViews en la misma pantalla.
* **Elevación:** El `webViewNeon` (carátula) se mantiene por encima del `webViewStudio` mediante elevación (`Elevation=10f`), impidiendo que el usuario vea la interfaz técnica de Google.
* **Transparencia Física:** En su estado estable, el WebView superior tiene fondos opacos para ocultar todo lo que corre atrás, pero conserva la capacidad de habilitar transparencias si se requiriera en futuras implementaciones de renderizado de video nativo.

## 2. LA CAPA FRONTEND: CARÁTULA WEB REACTIVA (PÁGINA 1)

Ubicada en la carpeta `40.-NEON-STUDIO-ANDROIT`, es una aplicación de React construida sobre Vite y optimizada para ejecutarse a pantalla completa en dispositivos móviles.

### A. Componente `NeonCoverLayer.tsx` (La Interfaz del Usuario)
Es la carátula visible del asistente. Se enfoca en una estética dorada premium sobre negro y contiene los siguientes elementos:
* **Botón de Videollamada (Cámara - Izquierda):** Al presionarse, inicia la llamada de video activando la webcam frontal de forma remota. Se ilumina con un anillo verde y una animación expansiva (`animate-ping`).
* **Botón de Silencio (Micrófono - Centro):** Permite pausar la captura de la voz del usuario (reservado para futuras integraciones).
* **Botón de Llamada de Voz (Teléfono - Derecha):** Permite iniciar una llamada de solo audio. Se enciende en rojo brillante, y **el icono del teléfono rota 135 grados** simulando un teléfono de colgar.
* **Cronómetro Central:** Mide la duración en segundos y minutos de la conversación activa y cuenta con un pulso de luz elegante.

### B. Gestión del Estado Local (`activeCallType`)
Para evitar fallas de renderizado globales, la carátula web controla qué luces encender usando una variable de estado estrictamente local:
```typescript
const [activeCallType, setActiveCallType] = useState<'video' | 'audio' | null>(null);
```
Este estado sincroniza los botones:
* Al presionar la cámara: `activeCallType` pasa a `'video'`. Solo el botón de la cámara recibe los estilos de luz verde.
* Al presionar el teléfono: `activeCallType` pasa a `'audio'`. Solo el botón del teléfono se ilumina de rojo y rota.
* Al colgar o si la llamada se cae: `activeCallType` se restablece a `null`, apagando ambos botones instantáneamente.

## 3. LA CAPA BACKEND: GOOGLE AI STUDIO (PÁGINA 2)

El `webViewStudio` carga la URL de Google AI Studio con el modelo `gemini-3.1-flash-live-preview`. Esta página corre una consola WebRTC en tiempo real que maneja la comunicación de la voz de la IA.

### A. Qué es la API de Gemini Live
A diferencia de las APIs tradicionales basadas en texto (donde envías un prompt y esperas una respuesta escrita), Gemini Live utiliza una conexión persistente **WebRTC** y **WebSockets**. 
* Envía continuamente el flujo de audio del micrófono y los fotogramas de la cámara del celular a los servidores de Google.
* Los servidores procesan la entrada y envían de vuelta un flujo de audio en tiempo real con la voz de la IA, reduciendo la latencia de respuesta a menos de un segundo (simulando una conversación humana natural).

### B. Captura de la Cámara y Micrófono
Al correr en un WebView con permisos otorgados a nivel nativo por `MainActivity.java`, Google AI Studio tiene acceso directo al hardware del dispositivo. Cuando los botones correspondientes son presionados virtualmente, el navegador abre el stream de video de la cámara y el canal de audio del micrófono del celular.

## 4. EL PUENTE DE COMUNICACIÓN (JAVASCRIPT BRIDGE)

El puente de comunicación (`WebAppInterface`) es la vía por la cual la carátula web (Página 1) le ordena al sistema operativo Android que ejecute comandos en Google AI Studio (Página 2).

### A. Método `startVoiceCall()` y Sobrecarga `startVoiceCall(boolean videoCall)`
Es el encargado de iniciar las llamadas simulando clics físicos en el DOM de Google AI Studio:

```java
@JavascriptInterface
public void startVoiceCall() {
    startVoiceCall(true); // Llamada por defecto con video
}
```

Si el parámetro `videoCall` es `true` (Botón de Video), inyecta un script secuencial de clics automáticos paso a paso:
* **Paso 1 (Segundo 1):** Busca en el HTML un botón cuyo texto o etiqueta `aria-label` sea `"webcam"`, y simula un clic para encender la cámara frontal.
* **Paso 2 (Segundo 2):** Busca y hace clic en el botón principal que contiene el texto `"talk"`, `"hablar"` o `"start"` para arrancar la llamada de Google.
* **Paso 3 (Segundo 3):** Busca y hace clic en el botón con icono de micrófono para asegurar que el audio no esté muteado.

Si `videoCall` es `false` (Botón de Audio), se ejecuta la lógica simplificada:
* Inyecta un script que busca el botón `"talk"` y **hace clic sobre él de forma inmediata**, omitiendo el encendido de la cámara frontal (llamada de solo audio).

### B. Método `endVoiceCall()` (Colgar la Llamada)
Cuando el usuario presiona el botón activo para colgar, se ejecuta este método que realiza las siguientes operaciones:
1. **Extracción de Transcripciones:** Corre un script en el DOM de Google que busca las etiquetas de texto con los roles de `User` y `Model`. Agrupa todo el texto en una lista formateada.
2. **Actualización de Memoria:** Envía el texto extraído al WebView superior de Neon para anexarlo a la memoria diaria de la IA en el almacenamiento local del celular.
3. **Corte del Canal WebRTC:** Ejecuta `webViewStudio.reload()`. Al recargar por completo la página web de Google, se destruyen al instante todos los sockets de comunicación y flujos de cámara y micrófono abiertos, colgando la llamada de inmediato de manera garantizada y segura.

### C. Método `updateSystemInstructions(String)`
Permite sincronizar de manera invisible las directrices de personalidad de la IA. React recopila las instrucciones de configuración y la memoria histórica del usuario, y las inyecta en una variable global en el segundo WebView:
```javascript
window.__phantomInstructions = 'Instrucciones del sistema + Memoria...';
```

## 5. EL SENSOR "WATCHER" DEL DOM (SUPERVISOR DE INSTRUCCIONES)

Dado que las instrucciones del sistema en Google AI Studio se ingresan mediante una caja de texto dentro de un menú lateral, no basta con inyectar el texto en una variable. Se requiere un **Watcher (Supervisor)** desarrollado en JavaScript que corre continuamente cada segundo en segundo plano en la Página 2:

1. **Paso 1:** Busca el botón de Ajustes (icono de engranaje o barra lateral) en Google AI Studio y simula un clic para abrir la barra lateral de configuración.
2. **Paso 2:** Localiza en la lista el panel plegable que dice `"System instructions"` y simula un clic para abrir la caja de texto correspondiente.
3. **Paso 3:** Busca la caja de texto (`textarea`) de instrucciones. Si el texto actual dentro de la caja es diferente al valor almacenado en `window.__phantomInstructions`, escribe el nuevo texto y dispara eventos de teclado (`input`, `change`) para obligar a Google a guardar la configuración.

EsteWatcher funciona de forma invisible para el usuario final, garantizando que el asistente siempre responda basándose en la memoria histórica del celular y las configuraciones de voz personalizadas.

## 6. PROCESO DE ACTUALIZACIÓN Y DESPLIEGUE EN PRODUCCIÓN

El mantenimiento del proyecto está dividido en dos flujos independientes según la capa que se modifique:

### 🌐 Despliegue de la Carátula Web (Carpeta 40)
Toda modificación visual de botones, animaciones, estilos dorados o lógica React se publica de la siguiente forma:

1. **Validación del Build Local:** Antes de subir cualquier cambio, ejecuta una compilación local para verificar que TypeScript o JSX no tengan errores:
   ```bash
   npm run build
   ```
2. **Subida a GitHub:** Si la compilación es exitosa, agrega los archivos modificados al repositorio y súbelos a la rama principal:
   ```bash
   git add .
   git commit -m "Explicación del cambio"
   git push origin main
   ```
3. **Compilación en Render:** Render.com detecta automáticamente el nuevo commit en GitHub, inicia el pipeline de integración continua, compila el sitio y lo distribuye a los servidores en un lapso de 2 minutos. La APK de tu celular se actualizará sola la próxima vez que inicie, sin necesidad de compilar nada en Android Studio.

### 🤖 Despliegue de la APK Android (Carpeta 45)
Si se modifican permisos del celular, el puente de Java, la carga de layouts XML o configuraciones del sistema nativo, se debe generar un nuevo archivo físico de instalación:

1. **Carga en Android Studio:** Abre la carpeta `45.-APK STUDIO NEON VIDEO` en la interfaz de Android Studio.
2. **Compilar APK Firmada:** Ve al menú superior en **Build -> Generate Signed Bundle / APK**.
3. **Configuración de Firma:** Selecciona la opción **APK**. En el campo de ruta de clave, selecciona el archivo `firma_neon` ubicado en la raíz de la carpeta 45. Introduce tus credenciales de firma autorizadas.
4. **Instalación:** Copia el archivo generado `app-release.apk` a tu dispositivo móvil e instálalo sobreescribiendo la versión anterior.

## 7. GUÍA DE PERSONALIZACIÓN DE ICONO Y NOMBRE DE LA APLICACIÓN

### A. Modificar el Nombre de la App en el Celular
El nombre que aparece debajo del icono se configura en los recursos de texto de Android:
* **Archivo:** `app/src/main/res/values/strings.xml`
* **Código:**
  ```xml
  <resources>
      <string name="app_name">ASISTENTE</string>
  </resources>
  ```

### B. Configurar el Icono en el Manifiesto de Android
Para apuntar a tus propios iconos personalizados en lugar de los genéricos de Android:
* **Archivo:** `app/src/main/AndroidManifest.xml`
* **Líneas a configurar en la etiqueta `<application>`:**
  ```xml
  android:icon="@mipmap/ic_launcher"
  android:roundIcon="@mipmap/ic_launcher_round"
  ```

### C. Conversión e Inyección del Icono (Solución al Error de Firma PNG)
**IMPORTANTE:** Android requiere estrictamente que los iconos `.png` tengan una firma interna real de PNG. No se puede simplemente renombrar un archivo `.jpg` a `.png`, ya que el compilador AAPT fallará con el error: *"failed to read PNG signature"*.

#### Script para convertir e inyectar el icono correctamente:
Si necesitas cambiar el diseño del icono en el futuro, guarda tu imagen en JPG (por ejemplo, generada con IA) y ejecuta el siguiente script en la consola de PowerShell para realizar la conversión correcta a PNG e inyectarla en todas las carpetas de resolución de la APK:

```powershell
# 1. Configurar rutas de origen (JPG) y destino (Carpeta de recursos res de la APK)
$src = "Ruta\A\Tu\Nueva\Imagen.jpg"
$baseDir = "C:\Users\cmcor\OneDrive\Escritorio\MEMORIA TOTAL NUEVA\NEON-AVANTAR-APP-WEB\45.-APK STUDIO NEON VIDEO\app\src\main\res"

# Densidades de pantalla requeridas por Android
$densities = @("mipmap-mdpi", "mipmap-hdpi", "mipmap-xhdpi", "mipmap-xxhdpi", "mipmap-xxxhdpi")

# 2. Cargar librería de procesamiento de imágenes .NET
Add-Type -AssemblyName System.Drawing

# Cargar la imagen JPG original en memoria
$img = [System.Drawing.Image]::FromFile($src)

# 3. Procesar y guardar en formato PNG real
foreach ($density in $densities) {
    $targetDir = Join-Path $baseDir $density
    if (!(Test-Path $targetDir)) {
        New-Item -ItemType Directory -Force -Path $targetDir | Out-Null
    }
    
    $pngPath = Join-Path $targetDir "ic_launcher.png"
    $pngRoundPath = Join-Path $targetDir "ic_launcher_round.png"
    
    # Convierte y guarda con firma física PNG verdadera
    $img.Save($pngPath, [System.Drawing.Imaging.ImageFormat]::Png)
    $img.Save($pngRoundPath, [System.Drawing.Imaging.ImageFormat]::Png)
}

# 4. Liberar memoria
$img.Dispose()
```

Después de correr este script, los iconos quedarán listos y corregidos. Abre Android Studio y genera la APK Release firmada normalmente.
